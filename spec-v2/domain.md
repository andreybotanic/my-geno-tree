# Доменная модель

## 1. Владение и границы данных

- Пользователь может иметь несколько деревьев.
- Дерево имеет ровно одного владельца.
- Дерево доступно для чтения и изменения только владельцу.
- Совместный доступ, публичные ссылки и роли участников не входят в MVP.
- Персона принадлежит ровно одному дереву.
- Все связи соединяют только персон одного дерева.
- Непустое дерево всегда является одним связным графом.

Попытка обратиться к чужому дереву или его вложенному ресурсу не должна раскрывать существование ресурса.

## 2. Пользователь

Пользователь содержит:

- UUIDv7;
- логин;
- нормализованный email;
- хэш пароля;
- предпочитаемый язык;
- ссылку на основной медиа-объект аватара либо `null`;
- дату создания;
- дату изменения.

Логин:

- длина от 4 до 32 символов;
- регистрозависимый;
- допустимы латинские буквы, цифры, `-` и `_`;
- пробелы запрещены;
- уникален с учётом регистра.

Email:

- обрезается по краям;
- нормализуется для регистронезависимых входа и уникальности;
- должен пройти базовую синтаксическую проверку.

Пароль:

- от 8 до 64 символов;
- только печатные ASCII-символы;
- пробельные символы запрещены;
- должен содержать минимум три категории из четырёх: строчная латинская буква, заглавная латинская буква, цифра, ASCII-спецсимвол.

## 3. Дерево

Дерево содержит:

- UUIDv7;
- владельца;
- название;
- опору обычного представления дерева;
- дату создания;
- дату последнего изменения;
- версию, представленную клиенту как непрозрачный hash/ETag.

Название:

- обрезается по краям;
- имеет длину от 1 до 100 символов;
- не может состоять только из пробелов;
- уникально у одного владельца с учётом регистра.

Пустое дерево не содержит персон. После создания первой персоны каждая новая персона добавляется через родительскую или супружескую связь либо связывается с уже существующей персоной.

Опора обычного представления имеет один из двух видов:

- одна персона дерева;
- канонически упорядоченная по UUID пара разных персон, между которыми существует хотя бы один период брака, включая расторгнутый.

Обе ссылки опоры могут быть `null` только у пустого дерева. Первая созданная персона назначается опорой в транзакции её создания.

## 4. Персона

Персона содержит:

- UUIDv7;
- дерево;
- фамилию при рождении;
- имя;
- отчество;
- пол;
- дату рождения;
- дату смерти;
- ссылку на основную фотографию либо `null`;
- дату создания;
- дату изменения.

Фамилия, имя и отчество являются независимыми известными или неизвестными значениями. Известная часть ФИО:

- обрезается по краям;
- не может быть пустой;
- может содержать Unicode;
- имеет длину не более 100 символов.

Все три части ФИО могут быть неизвестны. Такая карточка отображается как «Неизвестная персона».

Пол принимает значения:

- мужской;
- женский;
- неизвестно.

Фамилия в карточке всегда является фамилией при рождении. События смены фамилии не изменяют это поле.

Правила даты рождения и смерти определены в [dates.md](dates.md).

## 5. Родительские связи

Родительская связь содержит:

- UUIDv7;
- родителя;
- ребёнка;
- роль `father` или `mother`.

Инварианты:

- персона не может быть родителем самой себе;
- у ребёнка не более одного отца и одной матери;
- роль отца требует мужской пол;
- роль матери требует женский пол;
- если пол добавляемой персоны неизвестен, создание роли автоматически задаёт необходимый пол;
- если известный пол конфликтует с ролью, операция отклоняется;
- изменение пола отклоняется, если оно нарушит существующие родительские или брачные связи;
- создание связи не должно образовывать цикл предков;
- одинаковую связь нельзя создать повторно;
- у ребёнка может быть один или два известных родителя;
- родители ребёнка не обязаны состоять в браке.

Связь может быть создана с новой или уже существующей персоной текущего дерева.

## 6. Браки и семейные блоки

Период брака содержит:

- UUIDv7;
- мужчину;
- женщину;
- дату заключения;
- дату расторжения;
- дату создания;
- дату изменения.

Дата заключения обязательна как поле, но может иметь неизвестное значение. Значения даты расторжения описаны в [dates.md](dates.md#3-отсутствие-и-неизвестность).

Инварианты:

- брак возможен только между двумя разными персонами;
- пол обеих персон должен быть известен;
- допускаются несколько периодов брака одной пары;
- допускаются пересекающиеся периоды браков одной персоны;
- период брака не определяет родительство;
- удаление брака не удаляет родительские связи с общими детьми.

В интерфейсе один семейный блок соответствует одному партнёру. Он объединяет все периоды брака пары и список общих детей.

Если у ребёнка два известных родителя, не состоящих в браке, отдельный семейный блок для них не создаётся.

## 7. События

Событие содержит:

- UUIDv7;
- персону;
- тип;
- источник `automatic` или `manual`;
- дату;
- название;
- описание;
- данные конкретного типа события;
- ссылку на сущность-источник для автоматического события;
- ручной порядок внутри неоднозначной хронологической группы;
- дату создания;
- дату изменения.

Автоматические типы:

- рождение;
- смерть;
- вступление в брак;
- смена фамилии при вступлении в брак;
- расторжение брака;
- рождение ребёнка.

Автоматические события:

- создаются, изменяются и удаляются в одной транзакции с источником;
- недоступны для прямого редактирования и удаления;
- не должны дублироваться при повторной обработке операции;
- для рождения ребёнка создаются у каждого известного родителя;
- для брака и расторжения создаются у обеих персон;
- для смены фамилии создаются только у персон, для которых пользователь явно указал новую фамилию.

Ручные типы:

- смена фамилии;
- пользовательское событие.

Для ручной смены фамилии новая фамилия обязательна и не изменяет фамилию при рождении.

Для пользовательского события:

- название обязательно, обрезается по краям и имеет длину не более 200 символов;
- описание необязательно и имеет длину не более 5000 символов;
- описание является plain text с переносами строк;
- HTML и Markdown не поддерживаются.

## 8. Медиа

Файлы не должны храниться непосредственно в таблице пользователя, персоны или события. Используется отдельная модель медиа-объекта и типизированного вложения.

MVP использует:

- одно основное вложение для аватара пользователя;
- одно основное вложение для фотографии персоны.

Такая модель должна позволять позже добавить галерею и вложения событий без изменения правил хранения и доступа.

Требования к обработке и показу изображений приведены в [mvp.md](mvp.md#11-изображения).

## 9. Представления дерева

Обычное дерево не хранит координаты карточек. Его временная раскладка детерминированно вычисляется frontend только из родительских и супружеских связей и текущей опоры.

Силовая карта является отдельным представлением: она получает полный snapshot дерева и может сохранять собственные позиции узлов, параметры сил и viewport. Эти позиции не являются координатами персон и не участвуют в обычной раскладке.

## 10. Удаление

Удаление необратимо и требует явного подтверждения.

### Дерево

Удаление дерева удаляет всех его персон, связи, события, состояние силовой карты и медиа-вложения. Недоступные больше нигде медиа-объекты и физические файлы также удаляются.

### Персона

Удаление разрешено только при выполнении всех условий:

- у персоны нет родителей либо нет детей;
- у персоны нет общих детей с текущим супругом или супругой;
- удаление персоны и оставшихся связей не разделит другие персоны дерева на несколько компонентов.

При удалении персоны удаляются:

- сама персона;
- её события;
- её родительские связи;
- бездетные браки с её участием;
- её медиа-вложения.

Другие персоны не удаляются.

Если удаляется супруг из опорного брака, оставшийся супруг становится одиночной опорой. При удалении одиночной опоры случайно и равновероятно выбирается уникальный прямой родитель, ребёнок или супруг; после удаления последней персоны опора становится `null`.

### Связь

Родительскую связь можно удалить, только если оставшийся непустой граф дерева останется связным.

Удаление брака:

- удаляет выбранный период брака и его автоматические события;
- не удаляет общих детей;
- не удаляет родительские связи.

Удаление не последнего периода опорного брака не меняет опору. При удалении последнего периода случайно и равновероятно один из супругов становится одиночной опорой.

### Событие и фото

Ручное событие можно удалить. Автоматическое событие удаляется только вместе с источником.

Основную фотографию или аватар можно удалить отдельно. После удаления показывается соответствующий плейсхолдер.
