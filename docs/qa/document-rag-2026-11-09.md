# Документы дерева: ручная проверка 9 ноября 2026

Проверялись реальный Symfony AI agent, штатный `SimilaritySearch`, RabbitMQ,
Qdrant и Ollama `qwen3-embedding:0.6b`. Ответы ниже получены от рабочей модели,
без подмены embeddings и без передачи ожидаемых ответов агенту. Каждый из
13 запросов запускался в новой беседе, затем ответ вручную сверялся с исходником.
Это ручная приёмка, не автоматизированный E2E-тест.

## Доказательство выборочного поиска

Генератор `backend/tests/Fixtures/Documents/generate-corpus.php` создаёт восемь
вымышленных архивных книг с нейтральными именами `archive-01.txt` … `archive-08.md`:
400 записей в каждой, близкие по смыслу отвлекающие записи, RU/EN и редкие
искомые факты глубоко внутри файлов. Факты не вынесены в названия файлов.

Измерено: **1 609 926 исходных байт, 899 090 символов, 1128 чанков**. Размеры
и SHA-256 скачанных оригиналов совпали с локальными файлами, включая BOM.
Qdrant подтвердил ровно **1128 точек** для проверяемого дерева и конфигурацию
**1024 / Cosine**. Manifest с ожидаемыми сведениями агенту не загружался.

Показательный запрос №7 на английском к русскому тексту:

> Which family member used flashes of light to tell relatives across a river that the boat was ready? What did he build it from, and when?

Получен ответ о Савелии Андреевиче Чернове, 1928 годе и старом керосиновом
фонаре. Нужная запись — №0318 в `archive-06.md`, **чанк 111 при нумерации с нуля**,
примерно на 79% текста книги. Один вызов `similarity_search` передал модели
шесть фрагментов: **5420 символов, 0,6028% корпуса**. Целый файл содержит около
112 тысяч символов. Конец файла с контрольной строкой в результат не попал.

Запрос №3 на русском нашёл английскую запись о ремонте башенных часов:
один вызов, шесть фрагментов, те же **5420 символов**, нужный чанк №98.
Запрос №1 содержал ошибочную «жестянку»; агент нашёл фонарь, исправил неточность
и назвал человека, место и год. Здесь он сделал два поиска: 5420 и 6000 символов.
Ограничение шесть относится к одному поиску, а не сумме вызовов за весь ответ.

[Фактические результаты native tool calls](document-rag-retrieval-proof.json)
экспортированы из сохранённых `ToolCallMessage` Symfony AI. Артефакт содержит
точные аргументы, исходную JSON-строку результата, декодированные фрагменты,
номера чанков, длины и долю текста для каждого вызова, ответы агента и manifest.
Он позволяет проверить именно переданный модели контекст. Системные промпты,
токены авторизации и посторонние беседы в артефакт не включены.

Наличие случайных соседних фрагментов в выдаче ожидаемо для top-k без порога:
агент должен обосновывать ответ подходящей записью. Недостающий факт нельзя
объявлять отсутствующим во всём архиве с абсолютной уверенностью только по top-k.

## Воспроизведение корпуса

```sh
docker compose exec -T backend php tests/Fixtures/Documents/generate-corpus.php
```

Результат находится в игнорируемом `backend/var/rag-corpus`, включая manifest.
Загрузите восемь `.txt`/`.md` файлов в пустое тестовое дерево, дождитесь статуса
готовности и задайте вопросы из JSON. Manifest загружать не нужно. Ответы модели
могут различаться; оцениваются факты и использованные фрагменты.

В локальном аккаунте `demo` оставлено дерево
[RAG proof — 1.6 MB / 1128 chunks](https://my-geno-tree.localhost/trees/01a1bfe8-09d3-7146-907c-fe511d704816/tree)
с копией корпуса для повторения демонстрации. Служебные короткие файлы ручных
UI-проверок убираются после проверки; восемь оригиналов сохраняются.

## Интерфейс и качество

Реальный Chrome, локальный HTTPS: открытие из карточки, точный счётчик,
общие/личные привязки, загрузка нескольких файлов с независимой ошибкой формата,
появление статусов без перезагрузки и после обновления страницы. Проверен
отказ `412` при удалении с устаревшей версией после параллельного изменения;
исходный документ остался на месте. Контролы загрузки используют настоящий
файловый диалог; доступ расширения к file URLs включён пользователем.

В мультизагрузке `railway-letter.txt` и `family-notebook.md` сохранились,
`browser-unsupported.pdf` получил свою ошибку; счётчик вырос с 8 до 10.
«Личные» показал только два прикреплённых файла. После параллельной мутации
повторная отправка трёх файлов остановилась на первом `412`: результат только
для первого файла, остальные не отправлены, счётчик не изменился; предложено
обновление. При остановленном RabbitMQ `queue-retry.txt` сохранился с ошибкой
публикации. Скачивание из браузера создало файл 184 байта, SHA-256 совпал с
оригиналом (`772e9a9cb2c7357f869e4dca9ec3b75936bda0b757a2441e0e8da4c995b2be75`).
После восстановления RabbitMQ ручной повтор прошёл через очередь в готовность;
обе очереди затем пусты. Служебные три файла удалены, восемь книг сохранены.

Финальный интерфейс: в панели инструментов нет наложенной кнопки; документы
открываются из персоны, для пустого дерева — из пустого состояния. В модалке
карточки по 3–4 в ряд на широком экране, адаптивная сетка, кнопка скачивания с
SVG; переключатель «Все / Личные» непосредственно перед списком. В чате нет
текста фрагментов: только уникальные ссылки на файлы. Источники отделены от
ответа и имеют SVG-иконку фирменного цвета.

PhpStorm MCP, порт 64354, WARNING: проверены все 27 изменённых PHP-файлов,
доступные quick fixes применены. Остаток: ложные предупреждения Symfony-плагина
об аргументах конструкторов `TreeDocument`/`MediaVariant` (Doctrine entities
исключены из автозагрузки сервисов) и `SQL dialect is not configured` в миграции
(локальная настройка IDE). Подавления в код не добавлены. SQL проверен настоящими
миграциями и `doctrine:schema:validate`, включая новую пустую БД, down/up и повторную
проверку. Одноразовая БД затем удалена штатной Doctrine-командой.

Итоговые проверки: 300 backend, 458 frontend и 28 gateway тестов. Покрытие строк
93,71%, 91,10% и 98,45% соответственно; все изменённые production-файлы выше 75%.
В полном backend-отчёте два неизменённых шаблонных репозитория
`EventPlaceRepository` и `MediaVariantRepository` имеют по одной непокрытой строке
конструктора Doctrine и не содержат прикладного поведения. Тесты, повторяющие
эти конструкторы ради счётчика, не добавлялись.
PHPStan, CS/Twig/YAML/container lint, OpenAPI generation check, строгий
TypeScript, frontend/gateway lint и production builds прошли. Сохранились два
известных PHPUnit notices и прежнее предупреждение Vite о размере bundle.
Дополнительный интеграционный тест воспроизводит смену привязки в том же ORM
контексте: после пакетного отсоединения персоны повторный поиск обновляет
метаданные из БД и возвращает общий документ без повторной векторизации.

Один промежуточный полный прогон получил `302` вместо `429` в неизменённом
`MapTileApiTest` для лимитера с окном в одну секунду. Отдельный повтор всех
четырёх тестов карты и завершающий полный backend-прогон прошли; код карты
и её тестов в feature-коммит не включён.
